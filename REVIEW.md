# REVIEW.md

What matters when reviewing a change to ccmagic. Conventions for writing it are in `.claude/CLAUDE.md`. Template and section rules: `docs/REVIEW.md.example`.

## Failure modes

- Skills: they contradict. A `SKILL.md`, support file, or `agents/auto-*.md` that tells the model something another file it loads in the same run contradicts (a verdict rule, a handshake key, a grounding-block key, a step number) is High. The six `agents/auto-*.md` "Returning your report" and "No tracker access" paragraphs must stay identical.
- Grants: a skill calls a `bin/ccm-*` script, or a command, its `allowed-tools` does not grant, by path and by bare name. The run stalls on a permission prompt or a refusal. High.
- Scripts: they lie in JSON. A `bin/ccm-*` script whose output, exit code, or `-h` text disagrees with what a skill reads from it, or that exits 0 when it did not do the thing (a blocked redirect, a declined `rm`), is High.
- Autonomous runs: they merge or park wrongly. Anything that lets `/ccmagic:auto-ticket` merge past a failing check, review, or validate, or that parks a ticket a rule says should proceed, is Critical.
- Docs: they lie. README, CHANGELOG, or a skill's description that states behavior the code does not have is Medium.

## Skip

- `tests/every-ticket-since-baseline.diff` generated by `tests/run.sh`
- `tests/fixtures/**`

## Nit cap

3

## Evidence

Every finding cites a file and line. A finding about a script gives the command and input that show it, and a finding that two prompt files contradict quotes both lines.
